# VK Mini Apps

Интеграция адаптирована из проекта Void Storm и использует локально собранный пакет @vkontakte/vk-bridge 3.0.2. Игра определяет запуск по vk_app_id или предоставленному window.vkBridge. В обычном браузере и установленной PWA Bridge не загружается.

## Публикация

1. Выполнить npm ci и npm run build.
2. Разместить содержимое dist на HTTPS-хостинге.
3. Указать этот HTTPS-адрес в настройках своего приложения VK Mini Apps для нужных платформ.
4. Включить монетизацию приложения и доступные рекламные форматы в кабинете VK.
5. Открывать игру из VK с подписанными параметрами запуска; проверить показ на реальном устройстве.

ID приложения не зашит в исходники. Публикация игры на GitHub сама по себе не создаёт приложение VK и не включает монетизацию.

## Поведение

- После VKWebAppInit баннер запрашивается через VKWebAppShowBannerAd с bottom, resize и can_close:false. Для старых клиентов при коде 3/4 есть повтор с базовыми параметрами.
- При overlay резервируется фактическая banner_height, до 150 px. При resize повторного отступа нет.
- События обновления и закрытия баннера меняют отступ. Ошибка не блокирует игру; следующая попытка не чаще 60 секунд, при закрытии — от 15 секунд.
- Межэкранная реклама возможна по кнопке «Дальше» после двух завершённых задач продолжительностью от 15 секунд. Интервал между полноэкранными показами — минимум 120 секунд. Во время активной задачи или спринта автоматических показов нет.
- На поддерживающих клиентах используется VKWebAppShowInterstitialAd, при неподдерживаемом методе — VKWebAppShowNativeAds с ad_format:interstitial.
- Кнопка «Видео · +1» в магазине и AD на пустых кнопках подсказки/отмены запускает VKWebAppShowNativeAds с ad_format:reward.
- Одна подсказка или отмена выдаётся только при result:true. При нажатии AD на поле помощь сразу используется; если партия успела измениться, награда сохраняется в запас. Отказ, result:false, отсутствие результата, ошибка и таймаут награды не дают.
- Одновременные запросы блокируются. На время полноэкранной рекламы отключаются ввод и звук. Таймер спринта компенсирует время рекламы; события VKWebAppViewHide / ViewRestore также приостанавливают игру.
- Ошибка инициализации оставляет обычную игру рабочей.

## Сохранение в аккаунте

Используются VKWebAppStorageGetKeys, VKWebAppStorageGet и VKWebAppStorageSet. Хранилище VK относится к пользователю и приложению. Для проверки запускайте один и тот же app_id с одного VK-аккаунта на телефоне и ПК; самостоятельная ссылка GitHub Pages не авторизует игрока в VK.

Первое чтение запускается параллельно с загрузкой ассетов. Изменения отправляются автоматически, также выполняются чтение при возврате в приложение и проверка каждые 30 секунд. Ошибка чтения не считается пустым сохранением и не приводит к загрузке новых стартовых значений поверх облачных данных. При недоступности VK изменения остаются в локальной очереди до восстановления связи.

У каждого устройства своя запись: одновременная запись с телефона не перезаписывает запись ПК. Пройденные уровни, лучшие звёзды/ходы, темы, ежедневные задачи и достижения объединяются по идентификаторам. Одноразовые награды и темы учитываются один раз; покупки расходуемых бустов и их использование — отдельными накопительными изменениями. Спринт хранит лучший рекорд, количество ходов суммируется после миграции, идеальные уровни считаются по объединённым результатам. Настройки и выбранная тема используют логическую метку изменения. Текущая незавершённая партия остаётся на своём устройстве, обновление облака не подменяет её поле.

При первом обновлении старые локальные результаты обоих устройств сохраняются. Уже имеющиеся кошельки и запасы бустов объединяются по максимуму, а не складываются: в старой версии нет истории операций, которая позволила бы отличить одинаковые стартовые средства и повторные награды. После миграции расходы учитываются точно. Локальный старый слот сохраняется и импортируется только в первый VK-аккаунт на данном браузере; дальнейшие аккаунты используют отдельные слоты.

Записи сжимаются и разбиваются на части не более 1800 ASCII-символов. Сначала пишется неактивный набор частей, затем заголовок с SHA-256: оборванная передача не делает частичный файл актуальным. Запросы ограничены по частоте, ошибки повторяются с увеличением интервала. Локальный кэш содержит принятые записи и неотправленные изменения. Финансовую целостность против модифицированного клиента этот механизм не обеспечивает; для платной валюты потребовался бы доверенный сервер.

## Проверка

Автотесты подменяют Bridge: проверяют два независимых браузерных профиля с общим облаком, объединение старых сохранений, покупки, расход бустов, перезапуск без сети, переключение аккаунтов, большие сохранения и прерванные записи. Также проверяются резерв под баннер, старые клиенты, успешное/отменённое видео, однократность выдачи, восстановление таймера и частота межэкранной рекламы. Реальный рекламный инвентарь и доступность конкретных методов зависят от настроек приложения и клиента VK; их нельзя подтвердить localhost-тестом.

Официальные типы запросов: [VK Bridge](https://github.com/VKCOM/vk-bridge/blob/master/packages/core/src/types/data.ts), [методы Bridge](https://github.com/VKCOM/vk-bridge/blob/master/packages/core/src/types/bridge.ts).
